# Geometry figures

Use TikZ for precise, editable mathematical drawings. Local preparation compiles each figure with LaTeX and `dvisvgm --no-fonts`: labels become vector outlines, so a reader downloads neither a TeX engine nor additional diagram fonts. The SVG background stays transparent. Inline figures inherit the page's ink and adapt the muted green accent to dark mode.

## Writing in Obsidian

Keep a `.tikz` source and its generated `.svg` together, for example:

```text
Ridge/Diagrams/geometry-368/01-congruence.tikz
Ridge/Diagrams/geometry-368/01-congruence.svg
```

Embed the SVG where it belongs in the note:

```markdown
![[Ridge/Diagrams/geometry-368/01-congruence.svg|Congruent right triangles BPA and BCQ]]
```

Core Obsidian displays the companion SVG without a plugin. It does **not** compile TikZ or render a `tikz` code fence. The `.tikz` file is editable source for a code editor or the assistant; the user can simply request a drawing or a change, view the SVG, and write prose around it. No prose is generated by the diagram tool.

Regenerate the preview after editing its source:

```sh
npm run diagram -- "/absolute/path/to/01-congruence.tikz"
```

This writes only its companion SVG. It refuses to replace an unrelated, unmarked SVG. It doesn't select notes, change publication flags, export a vault, commit or push.

The source contains one `tikzpicture`, without a document preamble. The trusted wrapper provides `amsmath`, `amssymb`, and TikZ's `calc`, `angles`, `quotes` and `arrows.meta` libraries. `ridgeink`, `ridgeaccent` and `ridgemuted` are available colours. Use the same x/y unit for Euclidean circles and angles. General TeX macro programming and arbitrary packages are intentionally outside this drawing subset.

## Export and hosting

The local exporter recognises an embedded SVG only when an adjacent `.tikz` exists inside the vault. It ignores the SVG's bytes and recompiles the source. The generated, sanitized figure enters `content/diagrams/` and the body receives its reference at the authored position. Ordinary photos and audio retain their existing behaviour.

GitHub Pages builds consume that prepared SVG snapshot. They validate the SVG again and inline it; **TeX is not required in CI**, and no compiler runs in the reader. RSS uses the standalone SVG image as a fallback. Regenerating or exporting a changed drawing requires a local TeX Live/MacTeX installation with `latex`, TikZ/standalone, and `dvisvgm`; the current Mac already has it. This keeps the Pages toolchain small at the cost of a local authoring dependency.

## Compiler boundary

Source size and supported commands/environments are bounded. The wrapper rejects file access, preambles, TeX character escapes, arbitrary macros, shell commands and raw SVG specials. LaTeX runs with shell escape disabled, paranoid file IO, a private work directory and a timeout. The SVG parser accepts only a small set of vector elements/attributes, internal glyph references and fixed theme styling; it rejects executable markup, external references and HTML. Each inline instance gets distinct IDs. Raw post HTML remains escaped and arbitrary SVG attachments remain unsupported.

These are authored mathematical figures, separate from the deferred generated maps/charts/artefact system.

References: [TikZ coordinates](https://tikz.dev/tikz-coordinates), [dvisvgm vector outlines](https://dvisvgm.de/Manpage/).
